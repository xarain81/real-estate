# Reel Estate Singapore

A standalone React and Vite demonstration website for a multimodal ElevenLabs
property assistant.

## Local setup

This project expects Node.js 22.12 or newer.

```powershell
pnpm install
Copy-Item .env.example .env
```

Open `.env` and replace the placeholder with the public agent ID:

```text
VITE_ELEVENLABS_AGENT_ID=agent_your_public_agent_id
```

Do not add an ElevenLabs API key to this project. Vite variables are shipped to
the browser.

Start the local site with the saved Windows launcher:

```powershell
.\start-local.ps1
```

The launcher finds Node.js, starts Vite in the background, avoids duplicate
servers, and opens `http://127.0.0.1:4175` in your default browser. To start it
without opening a browser:

```powershell
.\start-local.ps1 -NoBrowser
```

The standard package-manager command remains available in a shell where Node.js
and pnpm are configured:

```powershell
pnpm dev
```

## ElevenLabs dashboard checklist

Before testing the embedded widget:

1. Open the agent in ElevenLabs and select **Widget** under the interface
   settings.
2. Enable **Voice + Text** so visitors can switch between chat and a voice call.
3. In the advanced settings, make the agent public and disable authentication.
   The standard website widget requires this.
4. In **Security**, add `localhost` and `127.0.0.1` to the allowed domains for
   local testing. Add a production domain only after it is approved.
5. Configure the widget’s display text, avatar or orb colours, terms, and
   language settings as required.
6. Restart Vite after changing `.env`, then test both Chat and Call.

Official reference:
[ElevenLabs widget customization](https://elevenlabs.io/docs/eleven-agents/customization/widget).

## Cloudflare Pages configuration

Connect the Git repository to Cloudflare Pages and use:

```text
Root directory: reel-estate-singapore
Build command: pnpm build
Build output directory: dist
Node.js version: 24.14.0 (pinned by .node-version)
```

Set `VITE_ELEVENLABS_AGENT_ID` as a plain-text build variable. The agent ID is
public configuration and will appear in the production JavaScript bundle. Do
not add an ElevenLabs API key, signed URL secret, or any other credential to a
`VITE_*` variable.

The site includes Cloudflare Pages security headers in `public/_headers`. After
deployment, verify that the widget can start text and voice sessions before
promoting the preview to production.

## Production abuse controls

The standard widget requires a public ElevenLabs agent, so abuse prevention is
configured in ElevenLabs rather than hidden in this static site:

1. Add only the final `pages.dev` hostname and approved custom domain to the
   agent Security allowlist. Add preview hostnames only while actively testing.
2. Remove `localhost` and `127.0.0.1` from the production agent allowlist.
3. Set a conservative maximum conversation duration, inactivity timeout, and
   concurrency or spending limits in ElevenLabs.
4. Keep tools least-privileged. Require confirmation before any calendar,
   messaging, CRM, or other state-changing action, and validate tool inputs
   server-side.
5. Keep the knowledge base free of secrets and instruct the agent not to reveal
   system prompts, private configuration, or unrelated records.
6. Monitor conversation volume, failures, tool calls, and unexpected cost, and
   disable the production hostname if abuse is detected.

For stronger access control than a domain allowlist, replace the public widget
configuration with signed URLs generated by a server-side Cloudflare Function.
Never generate signed URLs or store the ElevenLabs API key in browser code.
